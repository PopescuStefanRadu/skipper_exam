# Project instructions

## Read first

- `docs/DEVELOPMENT.md`: the development practices, especially the e2e-first loop.
- `docs/app/README.md`: the app overview (goal, platforms, technical direction, open points) and the index of feature documents. Each feature document in `docs/app/features/` holds that feature's behaviour and its e2e scenarios. `docs/app/features/content.md` describes how to update the question banks, the bibliography and the source links.
- `docs/DEPLOYMENT.md`: production (https://skipperexam.esrp.ro). The esrp.ro hosting project runs `deploy/compose.yaml` with the images `make integrate` publishes; HTTPS, the server and Authentik are its job, not this repository's. Requests to it go in pull-request descriptions, and changes to `.env` must be called out there.
- `docs/TODO.md`: open items that need a person, such as questions whose official answer seems to contradict the source.

Work **e2e-first**. Update the feature document and its e2e scenario before implementing, then iterate until the full e2e suite passes. Parallel tasks use one git worktree and branch each, with an isolated stack on free ports. Every test target records its run in `test-runs/<date>_<branch>_<sha>/` and refuses to run with uncommitted changes, so commit (a `wip:` commit is fine) before running tests. Commit the records along with your work. Changes reach `main` only through a pull request, using `make integrate`, which squashes the branch into one commit listing the original commit shas. Never push to `main` directly; GitHub blocks it. Pull-request descriptions and commit messages must not mention any AI tool. See `docs/DEVELOPMENT.md`.

## Commands

Use the `Makefile`. Run `make` on its own to list the targets.

```sh
make setup                 # install web/e2e dependencies and the Playwright browser (once per worktree)
make up / make down        # start/stop this worktree's stack; `up` writes the actual ports to .stack.env
make e2e                   # start the stack if needed, then run the e2e suite in parallel (all test targets need a clean, committed tree)
make e2e ARGS="-g 'deep link'"                        # run matching e2e tests only
make android-e2e           # build the Android app and run its Maestro flows on an emulator (Docker, needs /dev/kvm; part of test-all)
make android-build SERVER_URL=https://...   # debug APK for a server (default: this worktree's stack)
make screenshots           # screenshot tour: every screen on web and android, into test-runs/<run>/screenshots/ (not committed)
make test                  # Go tests
make test RUN=TestName PKG=./pkg/skipperexam/server   # a single Go test
make fmt                   # format Go code
make check                 # lint (gofmt check, vet, type checks) + Go tests
make deploy-test           # the production setup with this commit's images: start, sign in, back up, wipe, restore
make test-all              # check + e2e + deploy-test + android-e2e: what integration runs (there is no CI)
make publish               # build the production images from origin/main and push them to ghcr.io (integrate does it; needs a ghcr.io login)
make dev                   # web app with hot reload, using this worktree's backend
make grant-reviewer EMAIL=x   # give an account in this worktree's stack the reviewer role (after its first sign-in)
make content-extract       # extract the bibliography's text into content/bibliography/ (poppler; Docker for OCR)
make task-new NAME=x       # new worktree .worktrees/x on branch task/x, from the latest origin/main
make integrate TITLE="..." [NOTES=file] # inside a task worktree: squash, rebase, test-all, record, push, PR (NOTES: text for its description, e.g. .env changes), merge, publish images; repeats if main moves
make task-done NAME=x      # after the PR is merged: stop the stack, remove the worktree and the branch
```

## Architecture

- **Backend** (Go): `cli/server` is the entrypoint. It reads `DATABASE_URL`, `APP_URL` (its public address), `OIDC_ISSUER_URL`/`OIDC_CLIENT_ID`/`OIDC_CLIENT_SECRET` (the sign-in service), optionally `AUTHENTIK_URL`/`AUTHENTIK_API_TOKEN`/`AUTHENTIK_APP_GROUP` (account deletion), `CONTENT_DIR` (default `content`; `/content` in the image), `LISTEN_ADDR` (default `:8080`) and optionally `WEB_DIR` from the environment. At start-up it applies the database migrations (`pkg/skipperexam/db`, goose, SQL files embedded from `pkg/skipperexam/db/migrations/`) and loads the content. `pkg/skipperexam/server` holds the HTTP handlers: `/api/*` is the JSON API, and every other path serves the built web app, falling back to `index.html` for client-side routes. Postgres is accessed through `pgx/v5` (`pgxpool`). The app's own data about an account (the exam types it prepares for, one or several, `exam_types`) is in `profiles`, keyed by the account ID (`identity_id` columns hold `accounts.id`; `pkg/skipperexam/profile`); `GET/PUT /api/profile` read and change it, and `GET /api/exam-types` lists `content/exam-types.json`. `GET /api/content` serves the content package (`content.Package()`: questions, subjects, equivalence groups and each exam type's question IDs, with a content-derived version used as ETag). `GET/POST /api/events` read and append the account's events (`pkg/skipperexam/events`, table `events`): an append-only log with device-made UUIDs, so a resent event is stored once. `GET /api/explanations` returns every question's explanation with reviewers' decisions applied (`review.Effective()`; proposal notes only for reviewers), `POST /api/reviews` records a reviewer's decision (role checked; corrected quotes must be on their page), and `GET /api/sources/{id}` serves a bibliography PDF. `GET /api/account/export` downloads everything about the account and `DELETE /api/account` deletes it (`pkg/skipperexam/account`: the account with its progress, profile, roles and sessions goes, review decisions are kept but detached; inside the same transaction, `auth.Authentik` deletes the Authentik user if it's only in the app's group). Roles are in `roles`, reviews in `reviews` (`pkg/skipperexam/review`); the `server grant-role` subcommand assigns a role, looking the account up by email in `accounts`.
- **Accounts** (`pkg/skipperexam/auth`, `server/auth.go`): one way to sign in, "Continuă cu Google", through esrp.ro's Authentik as an OpenID Connect provider (Google only, open enrollment). The backend is the OIDC client: `GET /auth/login?platform=web|app&return_to=` stores a login request (state, nonce, PKCE verifier) and redirects to the provider (discovery is lazy, so the app starts without it); `GET /auth/callback` verifies the ID token (`auth.Provider`, go-oidc), creates or updates the account (`accounts`: own UUID, the provider's `sub`, email), then sets the website's session cookie (`skipper_session`, HttpOnly, Lax, Secure on https) or sends the Android app to `ro.skipperexam.app://auth?code=` with a one-time code it trades at `POST /auth/app-token`. Sessions are the app's own (`sessions`, SHA-256 of the token, a year from last use); `POST /auth/logout` ends one. Failures land on `/autentificare?eroare=1`. In the stack, a mock OIDC provider of our own (`cli/mock-oidc`, image `docker/mock-oidc`; per-sign-in state, so parallel sign-ins never mix up users or nonces) stands in for Authentik, in the app's network on a reserved port, so the app and the browser reach it at the same address; tests sign in through it with `signIn()` (`e2e/tests/helpers.ts`), and scripts with `e2e/sign-in.sh`.
- **Content** (`content/`, see `content/README.md`): stored source PDFs, `sources.json`, the shared question pool `questions.json`, and one file per RNA bank in `banks/`. `cli/content` imports and validates it. `pkg/skipperexam/content` holds the model and the import rules that keep question IDs stable (identical questions are shared across banks, slightly changed ones keep their ID). `pkg/skipperexam/content/rnapdf` rebuilds the RNA PDFs' Excel tables from their drawn cell borders, dropping hidden narrow columns. Each question has one subject, assigned by RNA number ranges in `content/subject-ranges.json` (`make content-tag`). Equivalent questions (same apart from diacritics, punctuation or case) are grouped by `EquivalenceGroups()` and share progress. `TestRealContentIsValid` validates the real content in every test run. The bibliography's text is stored page by page in `content/bibliography/<source>.json` (`content.ExtractText`: COLREG keeps only the Romanian left column, found from word positions; the scanned manual goes through the OCR image in `docker/ocr`). `content/explanations.json` links questions to quoted passages; validation checks every quote is on its page (`QuoteOnPage`, ignoring diacritics, punctuation and line breaks, and allowing 10% letter differences for OCR text). `go run ./cli/content search` and `check-quote` are the tools the proposal agents use.
- **Web app** (`web/`, React + TypeScript + Vite, pnpm): it calls the backend on the same origin under `/api`. All interface text is in `web/src/strings.ts`. The app works offline-first: `content.tsx` keeps the content package in local storage, `events.tsx` keeps the user's events there and syncs them with `/api/events`, and `exam.ts` builds exams (random questions, one per equivalence group, shuffled answers) and rebuilds their state and score from the events. `learning.ts` builds the answer history (practice answers, recorded as `practice.answered` events, and submitted exams' answers, per group of equivalent questions), coverage per subject and the mistakes to practise. Nothing about an exam or progress is computed on the server. The signed-in account is kept on the device too (`session.tsx`), so the app opens offline; events waiting to sync are shown on every signed-in screen and retried every 15 seconds.
- **Android app** (`web/android/`, Capacitor 8): the same web app in a web view on the origin `https://localhost`, built for one server address (`VITE_SERVER_URL`). `web/src/platform.ts` holds the differences: `apiFetch()` adds the server address and, in the app, the `X-Session-Token` header. Sign-in (`signin.ts`) opens `/auth/login?platform=app` in the browser; the app comes back through `ro.skipperexam.app://auth` and trades the code for a session token, sent as `X-Session-Token`. The backend allows the app's origin (`APP_ORIGINS`, default `https://localhost`; `cors()` in `server.go`). `scripts/android.sh` builds the APK and runs the emulator tests in the `skipper-exam-android` image (`docker/android`); `e2e/android/run.sh` drives the emulator and the Maestro flows in `e2e/android/flows/`, cutting the connection by removing the adb reverse tunnel.
- **E2E tests** (`e2e/`, Playwright): every test runs on two projects, `web` (Desktop Chrome) and `android` (Pixel 7: phone screen and touch in Chromium). `tests/screens.spec.ts` is the screenshot tour; a new screen or state gets a step there. They read the stack's addresses from `.stack.env` (`APP_URL`, `DATABASE_URL`, `MOCK_OIDC_URL`) and run fully parallel. Each test must create its own data (see "Parallel tests within a branch" in `docs/DEVELOPMENT.md`). Use the helpers in `e2e/tests/helpers.ts`: `signIn(page, email?)` signs in a new or given user through the fake sign-in service (the first sign-in creates the account). Tests that review explanations claim one first (`claimExplanation()` in `e2e/tests/review.ts`, R.N.D. ones only) and release it afterwards; read-only explanation tests use COLREG ones. Reviewers are created with `createReviewer(page)`, which signs in and runs the server's `grant-role` in the app container. Exam tests use the real content through `contentPackage()` and answer by the `data-question-id` of the question on screen; timers are driven by `page.clock`. After `signIn()`, wait for the resulting URL before calling the API with the page's cookies.
- **Stack**: `compose.yaml` and `Dockerfile` build one app image (Go binary + built web app on distroless) and run it next to Postgres 17.2 and the mock sign-in service. `scripts/stack.sh` names the Compose project after the worktree and lets Docker assign host ports, so stacks in different worktrees run side by side. The app's port and the mock sign-in service's port are the exceptions: the app must know both addresses before it starts, so `stack.sh` reserves free ports under the `ports` lock and holds the lock until Docker has bound them. `scripts/lock.sh` provides named locks shared by all worktrees; integration runs under the `integrate` lock.
- **Test runs**: `scripts/test-run.sh` runs the suites (`lint`, `go`, `e2e`, `deploy`, `android`) and writes the record of the run; every test target in the Makefile goes through it.
- **Production** (`deploy/`, `docs/DEPLOYMENT.md`): `deploy/compose.yaml` runs Postgres, the app and the `backup` service (`docker/backup/backup.sh`: a pg_dump every night, `restore <date>`) from the published images, configured by `.env` (`deploy/env.example`). `scripts/deploy-test.sh` (suite `deploy`, with `scripts/deploy-test.compose.yaml` adding the mock sign-in service) tests it end to end, including a restore.
- **No CI** for now: `make integrate` runs `make test-all` locally on the exact commit it merges, and after the merge `scripts/publish.sh` builds the `skipper-exam-{app,backup}` images from the merged files and pushes them to ghcr.io, tagged `latest` and with main's commit sha. `main`'s branch protection requires pull requests but no status checks.
